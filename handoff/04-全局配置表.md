## 1. 对战全局参数 `battle_globals.json`

```json
{
  "cards_per_player": 2,
  "skills_per_card": 6,
  "skills_selectable": 4,
  "talents_per_card": 2,
  "talents_selectable": 1,
  "draft_order": [2, 1, 1, 2],
  "pvp_turn_time_seconds": 30,
  "pvp_reserve_pool_seconds": 60,
  "pve_turn_time_seconds": -1
}
```

| 字段 | 含义 |
|---|---|
| `cards_per_player` | 双方各出战 **2** 张卡（2v2） |
| `skills_per_card` | 每张卡设计上有 6 个招式 |
| `skills_selectable` | 战前配置时**从 6 个里选 4 个**带入对战 |
| `talents_per_card` | 每张卡有 2 个可选天赋（通用池给的候选） |
| `talents_selectable` | 战前配置时**选 1 个**天赋 |
| `draft_order` | 轮选（Draft）顺序：**2-1-1-2**。A 选 2 张 → B 选 1 张 → B 选 1 张 → A 选 2 张 |
| `pvp_turn_time_seconds` | PvP 每回合免费思考时间 30 秒 |
| `pvp_reserve_pool_seconds` | 超时后从 60 秒储备池扣除；储备池耗尽即本回合**随机/默认行动**（见《02》§8.2） |
| `pve_turn_time_seconds` | `-1` = 不限时 |

> 战前配置（技能 6 选 4 + 天赋 1 选 1）双方**同时提交后一起公开**，不存在先手泄露信息。

## 2. 系别与克制

### 2.1 八系别

```json
["水", "火", "土", "风", "草", "雷", "灵", "战斗"]
```

外加一个合法显式值 **`none`**（无系别）。`none` **双向恒为 1.0**，且不参与多系别连乘
（它不改变乘积）。原稿中的「暗」系别统一映射为 `none`。

### 2.2 克制矩阵 `type_effectiveness.json`

**倍率只有三种取值**：`1.6`（克制）／`1.0`（中性）／`0.6`（弱化）。
键 = **攻击招式的系别**，值 = **目标卡牌系别 → 倍率**。

  "matrix": {
    "水":   {"水": 0.6, "火": 1.6, "土": 1.6, "风": 1.0, "草": 0.6, "雷": 0.6, "灵": 1.0, "战斗": 1.0},

### 2.3 矩阵的构造规则（四档分类）

8 系别分四档。**行 = 攻击方系别，列 = 被攻击方系别**。每档两条约束：

| 档位 | 系别 | 攻击时（行） | 被攻击时（列） | 自己对自己 |
|---|---|---|---|---|
| **防御类** | 水、土 | 弱化(0.6) 比 克制(1.6) 多 1 | 同左 | `0.6` |
| **平衡类** | 风、草 | 克制与弱化数量相等 | 相等 | `1.0` |
| **进攻类** | 火、雷 | 克制(1.6) 比 弱化(0.6) 多 1 | 多 1 | `1.6` |
| **超级进攻类** | 灵、战斗 | 克制比弱化多 **2** | 多 **2** | `1.6` |

全表 64 格分布：`1.6` 共 22 格、`0.6` 共 18 格、`1.0` 共 24 格。

### 2.4 克制关系**不互反**（有意设计，非笔误）

28 对非对角关系按「正反两格是否互为 1.6/0.6 镜像」分三类：

| 类别 | 对数 | 说明 |
|---|---|---|
| 互反（一方 1.6、另一方 0.6） | 10 | 符合直觉的那一类 |
| 双向中性（两方都 1.0） | 5 | 不构成克制关系 |
| **不互反** | **13** | 其中 12 对是「一方非中性、另一方 1.0」，1 对是「双向 1.6」 |

- 典型不互反例：`雷→战斗 = 1.6`，而 `战斗→雷 = 1.0`（不是 0.6）。
- **唯一双向都是 1.6** 的一对：`灵 ↔ 战斗`（互相克制）。这意味着灵/战内战纯拼出手顺序，双方都是 `×1.6`。
- **必须由 §2.3 的四档规则推出**，不能靠对称性简化存储。**不要**用「上三角 + 转置取反」实现。
- ⚠ 数据统计提示：若按「两格不相等」来数会得到 **22** 对，那包含 10 对正常互反关系。
  本文的「13 对不互反」是**扣除正常互反与双向中性**后的口径。
- ⚠ 连带 UI 硬需求：玩家无法从「我打他 ×1.6」推断「他打我 ×?」，
  **战斗界面必须内建一键查询全表的克制面板**，否则违背设计支柱「规则 5 分钟讲完」。

### 2.5 多系别结算（作者裁决）

```
克制系数 T = clamp( Π(矩阵[攻方每个系别][守方每个系别]),  0.3,  3.0 )
```

- **进攻侧系别数 × 防守侧系别数 = 连乘因子数**。双系打双系 = 4 个因子。
- 防守方多系别的来源包括：卡面本身多系、以及「运行时把目标视为多系」的招式效果（如玄武）。
- 截断发生在**克制层**；固定伤害与护盾结算在其之后。
- 单格取值仍只有 `{0.6, 1.0, 1.6}`，`[0.4, 2.5]` 只作用于**连乘后的最终乘积**。

## 3. 属性等级倍率 `stage_multipliers.json`

### 3.1 六维阶段倍率

定义式：**倍率 = `1.2 ^ stage`**，保留 3 位小数。范围 `−6 … +6`。

```json
{
  "formula": "1.2 ^ stage",
  "range": [-6, 6],
  "attack_stage_dimensions": ["atk", "dfs", "sp_atk", "sp_dfs", "spd", "crit"],
  "table": {
    "-6": 0.335, "-5": 0.402, "-4": 0.482, "-3": 0.579, "-2": 0.694, "-1": 0.833,
    "0": 1.000,
    "1": 1.200, "2": 1.440, "3": 1.728, "4": 2.074, "5": 2.488, "6": 2.986
  }
}
```

> ⚠ 不要把负档写成「对四舍五入后的正档取倒数」（`÷1.4`、`÷1.7`……）。那会引入第二个小数误差源。
> **正负两侧是同一幂函数的取值**，必须按 `1.2^stage` 计算或按上表查表，二者一致。

### 3.2 暴击系数倍率

定义式：**暴击系数 = `0.6 × 1.5 ^ crit_stage`**。

```json
{
  "formula": "0.6 * 1.5 ^ crit_stage",
  "table": {
    "-6": 0.053, "-5": 0.079, "-4": 0.119, "-3": 0.178, "-2": 0.267, "-1": 0.400,
    "0": 0.600,
    "1": 0.900, "2": 1.350, "3": 2.025, "4": 3.038, "5": 4.556, "6": 6.834
  }
}
```

暴击时的伤害乘数是 **`1 + 暴击系数`**（阶段 0 即 ×1.6）。

## 4. 暴击配置 `crit_config.json`

```json
{
  "base_crit_rate": 0.05,
  "speed_diff_coefficient": 0.001,
  "extra_crit_rate_cap": 0.50,
  "max_total_crit_rate": 0.55,
  "default_crit_coefficient": 0.6,
  "crit_stage_multiplier_per_step": 1.5,
  "slower_side_forced_base_only": true
}
```

```
暴击率 = 0.05 + max(0, 攻击方有效Spd − 目标有效Spd) × 0.001
若 攻击方有效Spd ≤ 目标有效Spd：暴击率 = 0.05（速度差不提供任何加成）
基础与速度部分 = min(暴击率, 0.55)
最终暴击率 = clamp(基础与速度部分 + 技能、被动及特性加成, 0, 1)
```

- 速度差500点打满速度额外上限，基础与速度部分最高55%，特殊加成后最高100%。
- 戏法空间中，双方用于暴击比较的速度均取负数，采用每次攻击当时的最新速度。
- 鲸鲨弑神刃每个成功暴击判定连续乘一次暴击倍率，0级三次成功为×4.096。
- 阶段 0 时暴击伤害乘数 = `1 + 0.6` = **1.6**。

## 5. 护盾配置 `shield_config.json`

```json
{
  "physical_shield_blocks": ["physical", "mixed", "fixed"],
  "spell_shield_blocks": ["spell", "mixed"],
  "spell_shield_physical_bypass": true,
  "overflow_on_break": "nullified",
  "shield_bare_gain_link": true
}
```

| 规则 | 内容 |
|---|---|
| **护盾位置** | 护盾是叠加在 HP **之上**的独立伤害池，不是 HP 的一部分 |
| **击破溢出** | 护盾被击破时，当次对应伤害通道的剩余伤害全部抵消；混伤的另一通道仍独立结算 |
| **物理护盾** | 抵挡物理伤害及混伤的物理分句；魔法攻击无视物理护盾。固定伤害保留原规则，由物理护盾抵挡 |
| **法术护盾** | 仅抵挡法术/混伤的法术分句；**物理攻击直接穿透**（无视护盾打 HP） |
| **增益绑定** | 部分护盾附带增益；护盾存在期间增益生效，护盾击破后增益立即消失 |

## 6. PP 与蓄力 `pp_config.json`

```json
{
  "core_skill_pp": [1, 3],
  "secondary_skill_pp": [4, 6],
  "basic_attack": { "power": 80, "pp": "infinite", "damage_type": "physical" },
  "charge": {
    "next_attack_multiplier": 1.5,
    "stackable": false,
    "chain_duration_turns": 3,
    "pp": "infinite"
  }
}
```

| 层级 | PP | 说明 |
|---|---|---|
| 核心技能 | 1–3 | 大招、强力控制、关键 Buff |
| 次要技能 | 4–6 | 常规攻击、小 Buff |
| 共享技能 `撞击` | 无限 | 每张卡战前配置时都可带入的通用招式：系别 战、`atk` 威力 **60** |
| 兜底普通攻击 | 无限 | 当 4 个已选招式 PP 全部耗尽时的默认输出：威力 **80** 的物理攻击（`basic_attack`） |
| 蓄力 | 无限 | 兜底选项之二：跳过本回合输出，换取下回合技能伤害 ×1.5 |

> ⚠ 上表第 3 行与第 4 行是**两个不同的东西**，威力也不同（60 vs 80）。
> 二者是否应当统一，属未决项，见《06》M-14。实现时先按两条独立配置存在。

## 7. 伤害通用常量 `damage_constants.json`

```json
{
  "min_defense_value": 150,
  "min_final_damage": 1,
  "fixed_damage_bypasses_defense": true,
  "fixed_damage_added_after_type_and_crit": true,
  "rounding": "floor"
}
```

- 物防与魔抗的计算先对「基础值 + 点数修正」应用最低 150，再乘以等级倍率；固定穿透随后从有效防御中扣除，除法分母最低为 1。
- 最终伤害 `floor()` 取整后 **保底 1**。
- 固定伤害（固伤）**不受克制与暴击影响**，在两者之后相加。

## 8. 行动优先级

| 配置 | 数值 |
|---|---|
| attack | 0 |
| support | 1 |
| first | 2 |
| last | −2 |

## 11. 数据校验规则（建议实现为加载期断言）

1. 每张卡恰好 6 个招式，且每项六维均为正整数。
2. 六维合计建议落在 `[2400, 4600]`（超出仅告警，不阻断）。
3. 每个招式的 `PP` 是正整数或 `infinite`；核心技 `1–3`，次要技 `4–6`。
4. 克制矩阵必须是 8×8 完整填充，且每格 ∈ `{0.6, 1.0, 1.6}`；
   行/列计数需满足 §2.3 四档规则（约束见《06》§1 L-09，测试用例见《06》§4 T-04）。
5. `card_id` 唯一，允许编号跳号（`25` 不存在是合法的）。
6. 天赋 `1–14` 为通用池；`15` 起为专属，专属天赋必须校验其持有者卡牌匹配。
