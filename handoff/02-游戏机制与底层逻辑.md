# 02 · 游戏机制与底层逻辑

> 本文档定义**规则本身**。数值常量在《04-全局配置表.md》，卡牌数据在《03-角色设定.md》。
> 三者冲突时：机制以本文档为准，数值以《04》为准，卡面以《03》为准。

---

## 1. 游戏是什么

**类型**：回合制战术卡牌对战（Turn-Based Tactical Card Battler）
**对阵**：2 人对战（PvP），双方各出战 **2 张卡牌**（2v2）
**平台**：Web 浏览器即玩
**单局时长**：15–30 分钟（含多场对战）

### 1.1 一局对战的完整流程

```
登录 → 大厅 → 建房/匹配
  → Draft 轮选（2-1-1-2 顺序，各选 2 张）
  → 战前配置（每张卡：6 个招式选 4 个 + 选 1 个天赋；双方同时提交后一起公开）
  → 回合循环 { 双方同时选定「招式 + 目标」 → 提交 → 按优先级与速度结算 → 回合末效果 }
  → 胜负判定（一方两张卡全部 HP 归零即败）
  → 对战结果展示
```

### 1.2 设计支柱（所有实现决策的仲裁依据）

| # | 支柱 | 对实现的含义 |
|---|---|---|
| **P1** | 每一回合都是心智博弈 | 胜负来自预判与反预判，不来自数值碾压。**不存在**「无条件造成 500 伤害」这类招式应被优先实现的路径；基于对手上一回合行动产生效果的招式是核心表达。 |
| **P2** | 搭配即武器 | 选卡、配招式、选天赋本身就是玩法。数据结构必须让「带哪 4 个招式」「带哪个天赋」成为**每局可变的玩家决策**，不是卡牌固定属性。 |
| **P3** | 翻盘永不关闭 | 战局可以倾斜，但不应在第 3 回合就定局。属性等级上限、克制截断、隐藏天赋触发都是为翻盘保留通道。**1v2 的战斗力差距必须被审视**（见《06》M-06）。 |
| **P4** | 简洁清晰，而非简单 | 规则 5 分钟讲完，精通需要上百场。**信息透明是硬要求**：结算面板必须显示「谁先动 → 用了什么 → 多少伤害 → 是否克制 → 是否触发天赋」，包括克制倍率被截断的标记。玩家不应因 UI 混乱而做错决策。 |

**反支柱（明确不是这款游戏）**：
- 不是数值碾压游戏（不做付费/肝度属性优势）
- 不是故事驱动 RPG（MVP 不追求剧情）
- 不是快节奏动作游戏（不需要手速与反应）

## 2. 六维属性与两层数值模型

### 2.1 六维

`HP`（生命）/ `Atk`（物攻）/ `Sp.Atk`（魔攻）/ `Dfs`（物防）/ `Sp.Dfs`（魔抗）/ `Spd`（速度）
外加派生维度 `Crit`（暴击等级）。

简称约定：**魔 = Sp.Atk，抗 = Sp.Dfs，防 = Dfs，攻 = Atk，速 = Spd，暴 = 暴击等级**。

### 2.2 两层数值模型（本游戏最重要的底层规则）

属性被两类**量纲不同**的效果修改，必须分别建模、分别存储：

- **点数层**：直接改基础数值（「+160 攻」「−180 最大生命」「增加 1/10 己速度点」）。
  **文本未标注时限者 = 永久**（本局对战内不还原）。
- **等级层**：改属性等级（±1 级 … ±6 级），等级通过乘数生效（`1.2^stage`）。
  按文本标注的时限还原。

**结算顺序（唯一一条，永久项与临时项不分叉）**：

```
有效值 = ( 基础数值 + Σ(所有尚未失效的点数增减) ) × Π(该维度的等级乘数)
```

> ⚠ 常见实现错误：把「当前属性值」存成单个数字。这样在点数 buff 到期时无法只回退点数项，
> 也无法保证临时点数增益享受等级乘数。**必须存 `base` + `point_modifiers[]` + `stage`，查询时现算。**

### 2.3 属性等级表

范围 `−6 … +6`，倍率 = `1.2 ^ stage`（完整真值表见《04》§3.1）。
每个可追踪等级的维度独立记录：`atk / dfs / sp_atk / sp_dfs / spd / crit`。

等级变更的来源：强化类招式（自身增益）、削弱类效果（对目标的减益）、净化类招式（清除）、
以及部分天赋的**锁定反转**（增益 ↔ 减益互换）。

## 3. 系别与克制

### 3.1 核心规则

- **攻击方系别来自招式**，**防守方系别来自卡牌**。两者**相互独立**。
  一张水系卡牌可以携带火系攻击招式，用它去打克制水系的对手 —— 这是刻意的战术空间。
- 倍率：克制 `×1.6`／中性 `×1.0`／弱化 `×0.6`（全表见《04》§2.2）。

### 3.2 三条系别规则（并存，必须区分）

| 规则 | 说明 |
|---|---|
| **真多系别** | 招式同时具有两个系别 → 克制系数**连乘** |
| **形态系别** | 角色按形态/属相**依次对应**不同单系别，**同时只取一个**（黑白无常白=灵/黑=战；红蝶三属相依次对应风/战/灵） |
| **运行时可变系别** | 系别在战斗中被写入/交换/指定，**不是静态字段**（银龙王按 HP 取模 7 定系别；泰坦交换系别；玄武令目标视为水+土双系） |

### 3.3 多系别克制计算（作者裁决）

```
T = clamp( Π( matrix[攻方系别][守方系别] for 攻方系别 in 进攻系别集合
                                     for 守方系别 in 防守系别集合 ),  0.4,  2.5 )
```

- **因子数 = 进攻系别数 × 防守系别数**。
- `none`（无系别）双向恒 `1.0`，不改变乘积。
- **截断发生在克制层**，固定伤害与护盾结算在其之后。
- 截断时 UI 必须显示截断标记（P4）。

### 3.4 克制关系**不互反**

本表**刻意不满足对称性**：`A 打 B = 1.6` 不蕴含 `B 打 A = 0.6`。
28 对非对角关系中有 13 对不互反；`灵 ↔ 战斗` 是唯一双向都是 `1.6` 的一对。

> ⚠ 这是由四档构造规则**逻辑必然推出**的结果，不是数据错误。
> **禁止**用「只存上三角 + 转置取反」的实现来节省空间。
> **禁止**在 UI 上假设「他克我所以我不克他」。
> ⇒ 连带硬需求：**战斗界面必须提供克制全表查询面板**（玩家无法自行推断反向倍率）。

## 4. 暴击

比较速度 = 有效速度 × 速度方向；戏法空间中方向为−1，其余为+1。

基础与速度暴击率 = min（55%，5% + max（攻击方比较速度 − 目标比较速度，0）×0.1%）。最终暴击率在叠加技能、被动及特性加成后限制在0%至100%。

单次暴击伤害倍率 = 1 + 0.6 × 1.5^暴击等级。总暴击伤害倍率 = 单次暴击伤害倍率^本段成功暴击判定次数。

- 基础与速度部分最高55%，速度差500点打满速度加成。暴击使用每段攻击结算当时的有效速度。
- 戏法空间立即反转暴击比较速度，原本低速者可对原本高速者取得速度差加成。施放当回合不重排已确定的行动队列。
- 默认每段攻击独立判定1次；鲸鲨弑神刃独立判定3次，每次成功均乘一次暴击倍率，0级时3次成功为1.6³=4.096倍。固定伤害不暴击。
- 暴击等级默认只影响伤害倍率，技能明确规定暴击率转换时另行处理。
- 圣灵麒麟的万王之荣耀在每次暴击及其效果结算完成后提高1级暴击等级，不提高本次伤害，后续攻击可享受提升。
- 随机数使用对局种子生成，重放与即时响应续算保持确定性。

## 5. 伤害公式

### 5.1 通用符号

| 符号 | 含义 |
|---|---|
| `P` | 招式威力 |
| `A` | 攻击方对应维度的**有效值**（§2.2 现算） |
| `D` | 目标对应维度的**有效防御值**；先将基础值及点数修正之和下限设为150，再扣除穿透点数，最后应用等级倍率 |
| `pen` | 固定穿透值 |
| `T` | 克制系数（§3.3） |
| `crit` | 本次是否暴击（外部注入的判定结果） |
| `K` | 暴击系数 = `0.6 × 1.5^crit_stage` |

有效防御 D = max（1，max（150，原始防御 + 有效点数增减）− pen）×1.2^防御等级。

例如500点物防、+2级，麒麟刺未暴击无视100点后按400×1.44=576点结算；暴击无视200点后按300×1.44=432点结算。

无尽蔚蓝次数 = 2 + floor（目标物防基础数值及点数增减之和 ÷70），不计入等级倍率；每段伤害仍使用有效防御。

### 5.2 物理伤害

```
伤害 = P × A_atk / max(1, D_dfs)
     × T
     × (crit ? 1 + K : 1)
     + 固定伤害
```

### 5.3 法术伤害

```
伤害 = P × A_sp_atk / max(1, D_sp_dfs)
     × T
     × (crit ? 1 + K : 1)
     + 固定伤害
```

### 5.4 混伤（第三条伤害管线）

**定义**：混伤 = 同时计算己方「攻、魔」及目标「防、抗」，两条管线各承担一半威力。

```
伤害 = 0.5 × P × A_atk     / max(1, D_dfs)
     + 0.5 × P × A_sp_atk  / max(1, D_sp_dfs)
     然后整体 × T × (crit ? 1 + K : 1) + 固定伤害
```

- 固定穿透值在物防、魔抗的点数层分别扣除，再应用各自等级倍率，不从已乘过等级的有效防御上直接扣除。
- 若目标有护盾：两条分句各自结算后再合并进入护盾流程。

**设计后果（调参前必须理解）**：
- 混伤**无视偏科防御墙**：目标只堆物防时，法术分句照样打满。堆单防对混伤收益减半。
- 代价是攻击方自己也不能偏科：物攻高而魔攻低的卡，混伤会被魔攻分句拖后腿。
- 双攻 500 打双防 500 时比值仍为 1.0 —— **混伤不改变数值尺度，只减小方差**。
  它是**破墙保险**，不是更强的第三选项。

### 5.5 固定伤害（固伤）

- 不经防御结算，**且不受克制倍率与暴击影响**。
- 在克制与暴击**之后**相加。

### 5.6 基准线

速度相同、等级 0、无克制、无暴击时：**招式威力 100 ≈ 造成 100 点伤害**。
（这是所有数值直觉的锚点：1000 HP 的角色约 10 发中性 100 威力招式阵亡。）

## 6. 蓄力机制

| 规则 | 内容 |
|---|---|
| 基本效果 | 消耗本回合不输出伤害，使**下回合**的攻击招式伤害 `×1.5` |
| 不可叠加 | 连续蓄力**不会**把倍率叠成 `×2.25`；状态不加深，只刷新 |
| 「蓄力使用时」 | 部分招式标注「蓄力使用时效果强化」，是**条件分支**而非另一套公式 |
| 蓄力连锁 | 使用带「蓄力使用」标注的招式后，**后续 3 回合**的招式自动获得蓄力效果（无需再次蓄力） |
| PP | 无限。所有招式 PP 耗尽后的默认选项之一 |

> ⚠ 「视为己蓄力」类效果（部分卡面文本）表示**把当前状态置为已蓄力**，
> 与真正消耗回合的蓄力共享同一个 `is_charged` 标志位，但**不消耗回合**。

## 7. 招式系统与行动优先级

### 7.1 招式类型

| 类型 | 说明 | 固有优先级 |
|---|---|---|
| **攻击** | 造成伤害（物理/法术/混伤/固伤） | `0` |
| **强化** | 提升/削弱属性等级，或施加特殊状态 | `+1` |
| **控制** | 眩晕、沉默等强制效果 | `+1` |
| **净化** | 清除属性等级变化或状态 | `+1` |
| **被动** | 满足条件时自动触发，**不占用行动** | 不参与排序 |

### 7.2 优先级层级

优先级从0起算，法术加1，先发加2，后发减2。同类时序标记只计一次，同时具备先发与后发时二者抵消。

| 优先级 | 包含内容 |
|---|---|
| 4 | 红蝶神圣相，固定优先级 |
| 3 | 先发法术 |
| 2 | 先发攻击 |
| 1 | 普通法术 |
| 0 | 普通攻击 |
| −1 | 后发法术 |
| −2 | 后发攻击 |

法术指非攻击、非被动的主动技能。物理、魔法、混伤和固伤攻击均属于攻击。
双方提交后，在回合结算开始时一次性记录优先级与有效速度并排定队列：优先级降序，同级速度降序，同速以对局种子随机。回合中不重排，暴击等实时计算仍使用最新状态。
戏法空间只反转同优先级的速度比较，不反转优先级。额外行动在触发位置响应并执行，不重新加入普通队列。

### 7.3 眩晕

- 先手方成功使用眩晕 → 后手方**本回合招式使用失效**
- 因控制效果导致招式发动失败时，默认不消耗 PP；只有招式效果明确写明仍消耗 PP 时才扣除。
- 眩晕成功率由各招式单独定义（**不是 100%**）
- 眩晕仅使本回合内下一次行动失败，触发1次后移除；未触发则在本回合结束时自动移除，不延续至下回合。
- 冰冻与眩晕不同：施加当回合仍可行动，下回合无法行动，下回合结束后移除；预先已知无法行动的角色无需选招或提交行动。
- 恐惧仅使持续期间下一次攻击失败，触发1次后移除；法术与蓄力不触发或移除恐惧。具体期限由技能决定：木灵兽「深渊斩」为施加当回合及下回合，共2回合；未触发则下回合结束移除。
- 不同控制状态独立保存；因眩晕等其他控制导致行动失败时，不会一并移除尚未触发的恐惧。

### 7.4 目标范围

| 范围 | 默认目标 | 说明 |
|---|---|---|
| **单体**（默认） | 指定的 1 个对方角色 | 绝大多数攻击招式 |
| **群体** | 对方**两个**角色 | 分别独立计算伤害（各自走完整公式） |
| **全场** | 场上**所有**角色（自己 + 队友 + 对方两个） | **必须**招式文本明确标注「全场」才生效 |

> 群体攻击默认**不打**自己与队友，除非文本明确写「全场」。

## 8. 回合结算流程

### 8.1 标准五步

1. 双方同时选定招式与目标并提交。
2. 处理回合开始效果，记录全体已提交行动的优先级、有效速度及同速随机值。
3. 按优先级4、3、2、1、0、−1、−2降序，同级按记录速度依次执行。
4. 每次攻击现算暴击与伤害，触发即时决策时等待响应，再继续原队列。
5. 处理回合末效果：被动、持续伤害与回复、状态到期及胜负判定。

队列生成后不动态重排。戏法空间生效期间，排序及暴击比较均使用取负的有效速度；施放当回合只有实时暴击计算立即改变。

### 8.2 时间与超时

- PvP 每回合免费 30 秒；超时后从 60 秒储备池扣除。
- 储备池耗尽后的行为**待作者裁决**（见《06》M-08），实现时先留出可插拔的策略位。
- PvE 不限时。

### 8.3 单次伤害的完整结算链（11 步）

这是**每次伤害事件**内部的执行顺序，必须严格按序，不得交换：

```
1.  读取有效攻击值 → A4.get_effective(skill.attack_basis)
2.  读取有效防御值   → A4.get_effective(skill.defense_basis)
        # 步骤 1 与 2 的取值维度【可以不同】
2b. 若 defense_basis == "none" → 跳过除法，M = P × A
3.  计算暴击率（§4）
4.  判定是否暴击          # 随机数由外部注入，本函数内部不掷骰
5.  查询克制倍率 T         # §3.3，取积后 clamp [0.4, 2.5]
6.  计算主伤害 M = P × A / max(1, D − pen)
7.  应用克制倍率  M = M × T
8.  应用暴击      M = M × (1 + K)（若暴击）
9.  加固定伤害    M = M + fixed_damage      # 不受克制/暴击影响
10. 取整与保底    M = max(min_final_damage, floor(M))
11. 若 skill.treated_as_attack == false → 输出 is_attack = false
```

第 11 步的存在理由：若干卡面与天赋的触发条件是「造成伤害时」「攻击时」，
而有些效果造成的伤害**不应被计为一次「攻击」**（不触发「受击后」「攻击后」类被动）。
`treated_as_attack` 是招式字段，`is_attack` 是结算输出的一部分，二者都要有。

## 9. 闪避

```
闪避概率 = 50% + (己方有效Spd − 敌方有效Spd) × 0.1%
```

- 己方速度**不低于**对方时，闪避率恒为 50%（速度差为正也不该无上限增长，
  实现须设上限；具体上限值**待作者裁决**，见《06》M-09）。
- 闪避判定同样属于**外部注入的随机事件**。

## 10. 确定性架构要求（最重要的实现红线）

本作是 PvP 同时提交制，**结算结果必须与服务端权威、可回放、双端一致**。由此推出：

### 10.1 结算逻辑零引擎依赖

战斗规则层（伤害公式、克制查询、等级计算、优先级排序、PP 状态机）必须是
**纯逻辑模块**，不引用任何引擎运行时类型、不触碰场景树、不读取节点。
目的：同一份规则代码既能在服务端无头环境跑，也能在客户端跑，还能被单元测试直接调用。

### 10.2 时间与随机必须从外部注入

纯逻辑层内**禁止**出现：
- 随机数生成（引擎的随机 API、语言内置随机）
- 读取系统时钟 / 帧计数
- 依赖迭代顺序未定义的容器（哈希集合在部分语言中不保证遍历顺序）

正确做法：结算函数接收 `rng_seed` 或预掷好的随机序列，以及显式的 `tick`/`turn_index`。
**给定相同输入与相同种子，输出必须逐字节一致。** 这是回放可行性的前提。

### 10.3 回放模型

```
服务端：接收双方选择 → 完整结算 → 广播「结算记录 SettlementRecord」（含每步的中间量）
客户端：只播放 SettlementRecord，**永不重新计算**
```

`SettlementRecord` 必须足以重建 P4 要求的结算面板：
谁先动、用了什么招式、打向谁、基础值/点数项/等级项各是多少、克制倍率及其是否被截断、
是否暴击与当时暴击率、护盾吸收了多少、溢出被抵消了多少、触发了哪个天赋、最终扣血。

### 10.4 深拷贝纪律

结算过程需要读写卡牌的可变状态（等级、点数修正、PP、状态层数）。
**不要使用引擎自带的高层深拷贝 API**（其语义与自定义对象耦合，且行为随版本变动）；
显式实现 `clone()`，或让状态全部落在可序列化的纯数据容器里。

## 11. MVP 范围

### 11.1 MVP 必须包含

1. 29 张卡牌（六维 + 6 招式 + 天赋候选）
2. Draft 轮选流程（2-1-1-2）
3. 战前配置（招式 6 选 4 + 天赋 1 选 1 + 双方同时提交后公开）
4. 回合制战斗引擎（同时选招+目标 → 优先级与速度排序 → 伤害计算 → 克制判定 → 天赋触发）
5. WebSocket PvP（建房 + 对战 + 时间系统）
6. 登录 + 游戏大厅 + 个人主页（最简版）
7. 回合结算展示 + 对战结果展示

### 11.2 MVP 明确不做

AI 对战 ／ 天梯·段位·赛季 ／ 卡牌收集与养成 ／ 好友与聊天系统 ／ 音效与音乐 ／
战斗回放（**注意**：§10.3 的 `SettlementRecord` 数据格式仍须现在设计，
因为它是结算广播的载体，不只是回放的前置）／移动端专门适配。
